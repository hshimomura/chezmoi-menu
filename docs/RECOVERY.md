# バックアップと復旧

## 保存場所

`~/Library/Application Support/ChezmoiMenu/Backups/<日時-ID>/` に保存します。メニューの「バックアップを開く」から Finder で確認できます。名前の日時は UTC です。

| 項目 | 内容 |
| --- | --- |
| `source/` | 同期前の source 全体と `.git`。未コミット変更を含む |
| `destination.json` | 元パス、コピー先、存在、種類、権限の対応表 |
| `destination/` | 管理対象のファイルとリンク。数字の名前は対応表で照合する |
| `original-head.txt` | 同期前の HEAD |
| `captured-head.txt` | Mac 側の編集をコミットした直後の HEAD |
| `external-source-edits/` | AI 解決中に source の競合ファイルが再編集されたとき、その編集内容を退避 |

バックアップには平文の dotfiles や秘密情報が含まれます。親ディレクトリは所有ユーザーだけがアクセスできる権限にします。共有や公開は避けてください。自動削除しないため、不要なものは利用者が削除してください。

## API / merge に失敗した

AI が拒否・未完了・解決不能を返した場合や、API が失敗した場合は、進行中の merge の中止を試みます。取り込み済みのローカルコミットは残します。Mac 側への apply と push は行いません。

実行履歴、source の `git status`、必要なら `git log` を確認します。中止そのものに失敗した場合は先に Git の操作を完了または中止し、手動で状態を整えてください。

## 統合後の apply が完了しなかった

`.git/chezmoi-menu-pending-apply.json` に、バックアップ先と統合後の HEAD を記録します。次回の同期を止め、古い Mac 側の内容を再取り込みして統合結果を失うことを防ぎます。

1. アプリの実行履歴とバックアップを確認します。
2. ターミナルで `chezmoi diff` を確認します。必要に応じて source を修正します。
3. 意図した内容になったら `chezmoi apply` を完了します。
4. アプリを再実行します。スクリプト以外の target と Mac 側が一致すれば記録を自動解除します。

独自の設定ファイルを使っている場合は、ターミナルでも同じ `--config` を指定します。apply の代わりにバックアップへ戻すと決めた場合は、現在の状態を別途退避して復旧したあと、記録ファイルも手動で削除してください。

## push が拒否・失敗した

Mac 側への apply とローカルコミットは完了済みの場合があります。ネットワーク・認証・upstream・リモートの更新を確認し、再実行します。force push で解決しないでください。

## バックアップから戻す

アプリを終了し、現在の source と Mac 側のファイルを別の場所へ退避してから復旧します。

- source 全体と履歴を戻す場合は、バックアップの `source/` を使用します。
- Mac 側は `destination.json` と照合し、必要なファイルやリンクを元のパスへ戻します。
- 同期前に存在しなかったファイルの削除、ディレクトリ構造、scripts / hooks / externals の副作用は手動で取り消します。

同期全体を自動で巻き戻す機能はありません。apply は途中まで成功する場合があるため、バックアップを source に戻しただけで Mac 側も元通りになるとは限りません。
